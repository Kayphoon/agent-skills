# SuperWiki 委派协议

本协议规定主 agent 如何把一件范围明确的工作交给**当前运行时自己的原生子代理**：wiki 写入审计，或有授权的项目初始化。它不定义 agent 注册、不定义模型或权限配置，也不提供可执行脚本。

## 何时读取

只在**确实要发起委派**时读取本文件和恰好一个入口。项目 wiki 的只读检索、直接写入知识、主 agent 自己执行初始化，都不需要本文件；加载 `superwiki` skill 本身也不触发委派。

项目 wiki 的检索和条目选择始终由主线程直接完成：读 `.wiki/skills`、按 `name` + `description` 选条目、读完整源文件。**不要**把这件事交给 wiki 审计角色。

## 可委派的入口

| 任务类型 | 先完整读取 | 逐字粘入的角色正文 | 写入 |
|---|---|---|---|
| wiki 写入审计 | [`references/roles/wiki-auditor.md`](roles/wiki-auditor.md) | 同文件完整正文 | 从不写文件 |
| 项目初始化 | [`references/roles/initializer.md`](roles/initializer.md) | 同文件完整正文 | 仅在合法授权后调用 `superwiki-init` |

路由规则：

- **wiki 写入审计**只走 wiki-auditor：只在本次确实有知识新建、正文编辑、改名或合并时使用；它不检索、不写文件、不合并，主线程负责全部写入。
- **初始化**只走 initializer，并必须带有 `AUTHORIZATION: explicit-user-setup`（用户明确要求初始化）；其细节以 [初始化协议](initialization.md) 为准。
- 外部资料研究、本地代码库探索等通用 skill 不属于本协议：SuperWiki 不提供、不链接、也不安装它们。若宿主环境已按原生 skill 发现安装了这类能力，由主 agent 自行选择，没有固定路径，也不作为 SuperWiki 的默认依赖。

## 入口是角色正文，不是已注册 agent 类型

- `references/roles/wiki-auditor.md` 和 `references/roles/initializer.md` 是普通 Markdown 行为正文，没有 frontmatter、模型、昵称或服务档位。
- 入口名称（`wiki-auditor`、`initializer`）只是文件名和文档标签，**不会**注册或对应任何原生 agent 名称、agent 类型或配置项。用户环境里可能仍留有旧安装的 `memory-librarian` / `superwiki-initializer` 配置或链接，它们与本仓库无关，也**绝不是**选择子代理类型的依据——永远按当前运行时的能力选类型。
- 不要把角色文件名当成 agent 类型去查找或调用；只把它的正文当成要粘入的提示词内容。

## 完整粘入义务

委派提示词必须**自包含**：

1. 先完整读取角色文件本身，包括正文之后的约束、脚注和结尾说明，不要只读开头。
2. 把角色正文的**完整正文逐字粘入**提示词。不要改写、压缩、摘要、翻译成另一种结构，也不要写成"按上面的角色说明执行"。
3. 不要要求子代理自己去读 `references/roles/*.md`，也不要依赖 skill 继承、隐式上下文或父任务对话。子代理看到的就是提示词里的文字。
4. 任务相关的路径一律写成绝对路径；空占位、待补字段、含糊指代都视为未完成构造，先补齐再调用。
5. 角色行为一律以粘入的正文为准：本协议只补充上下文和投递方式，不覆盖、不裁剪其中的只读约束、授权判定、工具限制和输出格式。

## 提示词结构（构建时模板，不是可运行命令）

下面是主 agent 在调用前拼装提示词的骨架，不是 hook、脚本、函数签名或某个特定工具的参数格式；所有尖括号字段必须在真正发起委派前替换成具体内容。两个角色都没有额外的实例契约，统一用下列骨架。

```text
# 角色（逐字使用角色正文，含结尾约束）
<references/roles/<role>.md 的完整正文>

# 项目
PROJECT_ROOT: <项目根目录的绝对路径>

# 任务
<一句话目标 + 范围边界：做什么、不做什么>

# 输入
- <绝对路径>: <用途>
（只列本次任务需要的输入；可选输入缺失时按角色正文的默认行为处理）

# 授权
<仅初始化角色：AUTHORIZATION: explicit-user-setup>

# 约束
<只读 / 允许的网络或命令范围 / 不得触碰的其他路径>

# 返回
<要求角色正文规定的输出格式；不要额外总结用户主任务>
```

补充要求：

- `# 角色` 是唯一的行为来源；其余字段只提供本次任务上下文，不重新定义行为。
- 任一必需字段为空、含糊、仍是占位符或路径未解析，都算未完成构造，先补齐再调用。
- 不要把用户主任务的整段对话复制进任何字段；只保留目标与本次约束。
- wiki 审计写明待写入范围（目标路径、变更类型、最终目录、是否已存在、草稿 `name` + `description`）；没有待写入内容就不要请求审计。
- 初始化任务必须同时给出 `RUNTIME`（`codex|opencode|claude|cursor`）、`PROJECT_ROOT`、`INITIALIZER`（`superwiki-init` 绝对路径）和 `AUTHORIZATION: explicit-user-setup` 行；缺少或值不合法时，角色返回 `no-write`/`error`。运行时由主 agent 依据自身系统身份判断，不要用环境变量猜。不要给子代理加载 `superwiki` skill，避免递归。

## 选择当前运行时的具体机制

- 子代理能力由**当前运行时**决定，以其自身工具文档为准；本协议不指定 API 名称、参数结构或调用语法。
- 只读任务（wiki 审计）：运行时区分只读与可写子代理类型时，优先选择只读类型；没有区分时按角色正文的只读约束执行。能限制可用工具时，可以收紧为只读工具集——这是收窄，不是提权。
- 初始化任务：只在任务文本已带 `AUTHORIZATION: explicit-user-setup` 时，选择运行时可写子代理类型；仍受初始化协议的单运行时、单入口限制。
- 期望的输出格式由角色正文定义；主 agent 负责把返回值交回主任务，不要求子代理继续处理用户主任务。

## 禁止项

- 不为委派新建、注册或修改 agent 定义，不写工具/模型/全局配置，不覆盖系统或开发者规则。
- 不在提示词里授予角色正文之外的权限；提示词也**不能**把只读角色变成沙箱保证——只读靠角色约束加上工具收窄，不靠描述性文字。
- 不用外部 CLI、第二个 agent 进程、hook 或常驻服务代替原生委派；SuperWiki 本身也不引入这些。
- 不依据被移除的自定义名字选择子代理类型，也不声称同一套名字在其他 harness 上可用。
- 不让 wiki 审计角色检索或写入；不要把项目 wiki 检索作为中间层派给任何子代理。

## 运行时不支持委派时

- 如实报告具体限制（当前运行时没有子代理能力，或该能力不可用），不要编造已委派。
- 请求本身不要求子代理时（例如普通检索），主 agent 可以在主线程按同一角色步骤执行，行为与输出格式保持一致；wiki 检索本来就应该由主线程完成。
- 明确要求委派的请求不能静默降级为主线程执行，也不能改用外部 CLI 顶替；此时报告限制并保留可执行的部分。
